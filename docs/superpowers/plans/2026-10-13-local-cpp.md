# Local C++ Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** C++ sample runs work locally without Docker, servers or compiler installation.

**Architecture:** The background router dispatches local C++ requests to a worker-backed service while preserving existing Piston consent. A compiler worker bundles browsercc; disposable WASI execution workers isolate and bound individual cases.

**Tech Stack:** Existing JavaScript/esbuild/Firefox WebExtensions; browsercc 0.1.1; browser_wasi_shim 0.4.2; node:test and Playwright.

**Spec:** ../specs/2026-10-13-local-cpp-design.md

## Global Constraints

- Firefox 128; original addon ID; version 3.1.0.
- Bundled assets only; no source transmission or remote fallback for local C++.
- C++20, 256 MiB program memory, 256 KiB output, 1 MiB source/input each.
- Load 60 seconds; compile 30 seconds; run 2 seconds; compiler idle release 60 seconds.
- Preserve existing editor/storage/submission flows and explicit Piston consent.

## Review Focus

- Cancellation during compiler loading and queued cross-tab jobs must settle without cancelling another tab.
- A reused module must receive fresh WASI state for every stdin.
- A worker crash or missing asset must permit a later fresh attempt.
- Settings and backup normalization must preserve explicit runner choice without granting remote consent.
- Firefox extension CSP must permit packaged Wasm while rejecting dynamic JavaScript evaluation.
